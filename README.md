# Практическое задание 3. Консольная программа для работы с CSV и XML файлами

Консольное приложение на Java, которое читает справочник адресов городов
из файла в формате CSV или XML и формирует по нему сводную статистику:
дублирующиеся записи, количество 1–5-этажных зданий в каждом городе и время обработки файла.

## Возможности

- Чтение справочника из CSV и XML, формат определяется по расширению файла
- Поиск дублирующихся записей с количеством повторений
- Подсчёт 1, 2, 3, 4 и 5-этажных зданий в каждом городе
- Замер времени обработки файла
- Обработка нескольких файлов подряд без перезапуска программы
- Завершение работы только по команде `exit` или комбинации Ctrl+D
- Обработка ошибок без аварийного завершения

## Формат файлов

CSV — поля разделены `;`, первая строка — заголовок:
```
"city";"street";"house";"floor"
"Барнаул";"Дальняя улица";56;2
```

XML — каждая запись хранится в атрибутах элемента:
```xml
<root>
<item city="Барнаул" street="Дальняя улица" house="56" floor="2" />
</root>
```

Файлы справочника `address.csv` (143 МБ) и `address.xml` (226 МБ) не хранятся в репозитории,
потому что они больше лимита GitHub в 100 МБ. Перед запуском их нужно положить в корень проекта.

## Как считается статистика

- **Дубли** — записи, у которых совпадают город, улица, дом и этажность.
  Количество повторений считается в `HashMap<Address, Integer>` за один проход по записям
- **Этажность** — для каждого города хранится массив из 5 счётчиков.
  Считаются уникальные здания: повторы одного дома не учитываются несколько раз
- **Время обработки** — от начала чтения файла до конца подсчёта статистики

Записи хранятся в `HashMap`, поэтому поиск дублей и подсчёт этажности работают
за линейное время от размера файла.

## Скорость работы

На файлах справочника (2 310 991 запись, 49 городов):

| Файл          | Чтение | Подсчёт статистики | Всего  |
|---------------|--------|--------------------|--------|
| `address.csv` | ~1,3 с | ~0,5 с             | ~1,9 с |
| `address.xml` | ~1,4 с | ~0,5 с             | ~2,0 с |

Для скорости:
- CSV читается построчно через `BufferedReader`, XML — потоково через StAX,
  файл не загружается в память целиком
- `HashMap` для подсчёта создаётся сразу нужного размера и не перестраивается при росте
- `Address` вычисляет `hashCode` один раз в конструкторе

## Обработка ошибок

| Ситуация                                | Реакция программы                                    |
|-----------------------------------------|------------------------------------------------------|
| Пустой ввод                             | просит ввести путь ещё раз                           |
| Путь в кавычках («Копировать как путь») | кавычки убираются автоматически                      |
| Путь с недопустимыми символами          | сообщает о некорректном пути                         |
| Файл не найден                          | сообщает об этом и ждёт новый путь                   |
| Указана папка вместо файла              | сообщает об этом и ждёт новый путь                   |
| Неподдерживаемое расширение             | перечисляет поддерживаемые форматы                   |
| Повреждённый XML                        | сообщает, в какой строке ошибка                      |
| Файл без записей справочника            | сообщает, что записи не найдены                      |
| Некорректные строки в файле             | пропускает их и показывает, сколько пропущено        |
| Ошибка в файле настроек                 | сообщает, какой параметр неверен, и завершает работу |

## Настройки

Параметры вынесены в `src/main/resources/application.properties`,
чтобы менять их без правки кода:

| Параметр        | Назначение                        | Значение по умолчанию |
|-----------------|-----------------------------------|-----------------------|
| `exit.command`  | команда завершения работы         | `exit`                |
| `csv.separator` | разделитель полей в CSV           | `;`                   |
| `max.floors`    | до какой этажности считать здания | `5`                   |

## Технологии

- Java 27
- Maven
- StAX (`javax.xml.stream`) — потоковое чтение XML, входит в JDK
- Сторонних библиотек нет

## Сборка и запуск

Требуется установленная JDK 27+ и Maven.

1. Положить `address.csv` и `address.xml` в корень проекта
2. Открыть проект в IntelliJ IDEA и запустить класс `citydirectory.Main`
3. Ввести путь к файлу. Можно указать полный путь или просто `address.csv`:
   относительные пути считаются от корня проекта

Ввод читается в кодировке UTF-8. В консоли IntelliJ IDEA пути с русскими буквами работают корректно,
а в стандартной консоли Windows их лучше не использовать.

## Структура проекта

```
src/main/java/citydirectory/
├── model/        Address — запись справочника, ParseResult — результат чтения файла,
│                 CityStatistics — результат подсчёта
├── parser/       AddressParser — общий контракт парсеров,
│                 CsvAddressParser, XmlAddressParser — реализации,
│                 ParserRegistry — выбор парсера по расширению файла
├── statistics/   StatisticsCalculator — подсчёт дублей и этажности
├── input/        ConsoleInput — ввод пути к файлу и команды выхода
├── output/       StatisticsPrinter — вывод статистики и сообщений
├── app/          CityDirectoryApp — главный цикл программы
├── config/       AppConfig — чтение файла настроек
├── exception/    DirectoryFileException — ошибка работы с файлом справочника
└── Main.java     точка входа: создаёт объекты, регистрирует парсеры и запускает приложение
src/main/resources/
└── application.properties   настройки приложения
```

- Парсеры CSV и XML реализуют общий интерфейс `AddressParser`, поэтому остальная программа
  не зависит от формата файла. Новый формат добавляется одной строкой в `Main`:
  `parsers.register("json", new JsonAddressParser())`
- Каждый класс отвечает за одну задачу, `CityDirectoryApp` только вызывает их по порядку
- Зависимости передаются через конструктор, все объекты создаёт `Main`
- Ошибки работы с файлом переводятся в `DirectoryFileException` с понятным сообщением,
  главный цикл выводит его и продолжает работу

## Работа с репозиторием

- Ветка main содержит только проверенный код; прямые коммиты в неё не делаются
- Каждая задача ведётся в отдельной ветке (feature/..., fix/..., docs/...)
- Изменения попадают в main через Pull Request после ревью второго участника
- Сообщения коммитов оформляются так:
  feat:, fix:, refactor:, docs:, chore:
